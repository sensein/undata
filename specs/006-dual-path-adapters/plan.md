# Implementation Plan: Dual-Path Schema Adapters

**Branch**: `006-dual-path-adapters` | **Date**: 2026-03-10 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/006-dual-path-adapters/spec.md`

---

## Summary

Extend all five ingestion adapters (BIDS, DANDI, NWB, openMINDS, AIND) with explicit
`load_code()` and `load_file()` methods so callers can choose which extraction path to use.
Add `extract_elements(mode)` and `extract_classes(mode)` supporting `"code"`, `"file"`, and
`"both"` modes. The "both" mode merges and deduplicates by `source_local_id`, logging conflicts.
Update the CLI `ingest` command with `--extraction-mode` and `--source-path` flags.

JSON-serialised element data on stdout, and deserializes it into native Python types. No
bridge-venv packages are imported directly into the 3.14 process. Bridge dependencies declared
in `ingestion/pyproject-bridge.toml`.

## Architecture Decisions

### AD-001: Explicit named methods over mode parameter on `load()`

`load_code()` and `load_file(path_or_url)` are separate methods rather than a single
`load(mode=..., path=...)`. This makes Protocol conformance checkable at the class level
and avoids optional parameter combinations.

The existing `load()` method is retained as a compatibility shim pointing to `load_file()`.

### AD-002: Mode-dispatched `extract_elements()` and `extract_classes()`

Both `extract_elements(mode)` and `extract_classes(mode)` accept `ExtractionMode` and dispatch
internally. Merging is done inside the adapter because only the adapter knows how to run both
paths. The pipeline remains unaware of the mode.

### AD-003: `extraction_path` semantics change + new `schema_format` field

`SchemaClassPayload.extraction_path` changes from format-specific ("json"/"yaml"/"jsonld") to
path-type ("code"/"file"/"both"). Format information moves to a new optional `schema_format`
field. The backend stores `extraction_path` as informational only — no migration required.

### AD-004: AIND code-path: hard ImportError, no fallback

If `aind-data-schema` is not importable, `AINDAdapter.load_code()` raises `ImportError` with
a descriptive message naming the missing package. No silent fallback to file path. This matches
the edge case requirement in the spec.

### AD-005: Turtle format as explicit `load_turtle(path)`, not part of `load_file()`

To keep `load_file()` format-predictable (JSON-LD for openMINDS, YAML for NWB/BIDS, JSON for
AIND/DANDI), Turtle/RDF support is offered via a separate `load_turtle(path)` method on
`OpenMINDSAdapter`. This is explicitly in the spec (FR-008) but does not affect the Protocol.

## Phase Plan

### Phase 1 (Setup + Foundational)

- `ExtractionMode` type alias in `models.py`
- `AdapterResult` dataclass in `models.py`
- Update `SchemaClassPayload` with `schema_format` field, `extraction_path` default `"file"`
- Update `SchemaAdapter` Protocol in `base.py`
- Contract test for Protocol conformance

### Phase 2 (User Story 1 — File-path for all adapters)

- `DANDIAdapter.load_file(path_or_url)` — JSON Schema `$defs` parser
- `BIDSAdapter.load_file(path)` — promote existing raw YAML code to named method
- `NWBAdapter.load_file(path)` — promote existing YAML code, add namespace include traversal
- `OpenMINDSAdapter.load_file(path)` — promote existing; support directory glob
- `AINDAdapter.load_file(path)` — promote existing JSON Schema dir reader
- Tests: unit for each adapter file-path using existing fixtures

### Phase 3 (User Story 2 — Code-path for all adapters)

- `BIDSAdapter.load_code()` — bidsschematools bundled schema
- `NWBAdapter.load_code()` — pynwb/hdmf namespace registry
- `OpenMINDSAdapter.load_code()` — openminds registry introspection
- `AINDAdapter.load_code()` — Pydantic introspection + ImportError on Python 3.14
- `DANDIAdapter.load_code()` — rename/promote existing `load()` implementation
- Tests: unit for each adapter code-path

### Phase 4 (User Story 3 — Dual-path merge)

- Shared `_merge_elements()` utility in `adapters/merge.py`
- `extract_elements(mode="both")` and `extract_classes(mode="both")` for each adapter
- Tests: merge logic, dedup, conflict detection

### Phase 5 (CLI + Polish)

- `--extraction-mode` and `--source-path` flags on `undata ingest`
- Update `_get_adapter()` to configure mode before `load_code()`/`load_file()`
- Lint (ruff check + ruff format)
- Verify all 68 existing tests still pass

| AIND code-path Python 3.14 incompatibility | Hard ImportError per FR-013/AD-004 |
| BIDS raw YAML directory structure varies by version | Accept `objects/metadata.yaml` as entry; warn if missing |

**Implementation note (I1 resolved 2026-03-11)**: The Technical Context section above describes
a bridge venv (`.venv-bridge-schema`) for invoking `hdmf`/`pynwb`/`openminds-python` via subprocess.
During implementation, the simpler direct-import-with-ImportError approach was chosen instead:
each adapter's `load_code()` does a try-import and raises `ImportError` with a descriptive
message if the library is unavailable. This satisfies all spec requirements (FR-011/FR-012/FR-013)
and the constitution VI Bridge Venv Exception's "MAY be created" language (the exception permits
but does not require bridge venvs). Unit tests mock the libraries. Production users who need
the code-path must install the library in a compatible Python environment.
