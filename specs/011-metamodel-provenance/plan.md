# Implementation Plan: Metamodel, Provenance & LinkML I/O

**Branch**: `011-metamodel-provenance` | **Date**: 2026-03-12 | **Spec**: `specs/011-metamodel-provenance/spec.md`
**Input**: Feature specification — PROV-O provenance endpoints, schema_ref FK, LinkML import/export, meta-model YAML

---

## Summary

Extend the `backend` service with:
1. An Alembic migration adding `schema_ref` FK on `data_element` and `status`/`attributed_to`/`confidence_score` on `mapping_function`.
2. PROV-O Pydantic models generated from a hand-curated OWL→LinkML conversion (`backend/data/prov-o.linkml.yaml`).
3. A `provenance` service and router that assembles PROV-O JSON-LD from `AuditLog` / `SchemaChangeLog` rows.
4. A `linkml_io` service for schema export (YAML + fidelity score) and import.
5. A `PUT /mappings/{id}/accept` endpoint for confidence-gated curation of system-inferred mappings.
6. A `docs/undata-metamodel.yaml` LinkML meta-model + GitHub Actions workflow for gen-doc publishing.

## Implementation Phases

### Phase 1 — Setup & Code Generation (blocking)

1. Add `linkml-owl` to `backend/pyproject.toml` dev dependencies.
2. Run `linkml-owl-to-linkml` against the PROV-O OWL file, prune to 6 classes, save as `backend/data/prov-o.linkml.yaml`.
3. Run `gen-pydantic backend/data/prov-o.linkml.yaml --output backend/src/models/prov_o.py`.
4. Commit generated files.

### Phase 2 — Database Migration

1. Write Alembic migration `0010_schema_ref.py`:
   - `data_element.schema_ref UUID FK → dynamic_schema(id) ON DELETE SET NULL`
   - `mapping_function.status VARCHAR(32) NOT NULL DEFAULT 'active'`
   - `mapping_function.attributed_to TEXT`
   - `mapping_function.confidence_score FLOAT`
2. Update SQLAlchemy ORM in `db.py`.
3. Run migration in test Docker Compose; verify `alembic upgrade head`.

### Phase 3 — Provenance Service & Endpoints (US1, US2)

1. Implement `backend/src/services/provenance.py` — `audit_log_to_bundle()` and `changelog_to_bundle()`.
2. Implement `backend/src/api/v1/provenance.py` — FastAPI router, `application/ld+json` responses.
3. Register router in `main.py`.
4. Write contract tests in `tests/contract/test_provenance_api.py`.

### Phase 4 — LinkML I/O Service & Endpoints (US3, US4)

1. Implement `backend/src/services/linkml_io.py` — `export_schema()` + `import_schema()` + `RoundtripResult`.
2. Extend `backend/src/api/v1/schemas.py` with LinkML routes.
3. Write contract tests in `tests/contract/test_linkml_io_api.py`.

### Phase 5 — Mapping Accept Endpoint (US derived from clarifications)

1. Extend `backend/src/api/v1/mappings.py` with `PUT /mappings/{id}/accept`.
2. Update `MappingService` to handle `status` + `confidence_score` logic.

### Phase 6 — Meta-model YAML + GitHub Actions (US5)

1. Write `docs/undata-metamodel.yaml`.
2. Write `.github/workflows/metamodel-docs.yml`.
3. Validate with `gen-doc` locally.

## Complexity Tracking

No constitution violations. All additions are direct requirements with no speculative abstractions.

| Design Choice | Justification |
|---------------|---------------|
| JSONB provenance (on-demand assembly) | Simpler than a dedicated provenance table; existing AuditLog + SchemaChangeLog sufficient |
| gen-pydantic from OWL-derived LinkML | Avoids `prov` library dependency; gives typed Python models for free |
| No new microservice | Provenance is a read-only view over existing data; no async job needed |
